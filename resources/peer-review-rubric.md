# Skill Peer Review Rubric
## Tech Writer's Tribe | AI-Powered Documentation Mastery

Use this rubric when reviewing a classmate's skill in Module 5, and any time you're reviewing skills for your team.

---

## How to Review

1. **Read** the skill file from top to bottom *(not the output — the skill itself)*
2. **Run** the skill on a test file (e.g., `test-docs/bad-api-doc.md` or a relevant document)
3. **Score** each criterion (1–3)
4. **Write** specific feedback for any criterion scored 1 or 2
5. **Share** your completed rubric with the skill author

---

## Scoring Scale

| Score | Meaning |
|-------|---------|
| **3** | Strong — clear, complete, no confusion |
| **2** | Adequate — works but could be sharpened |
| **1** | Needs work — unclear, incomplete, or missing |

## Criterion 3: Checklist / Rules (Score: __ /3)

**Are the criteria or rules explicit, complete, and unambiguous?**

| Score | Description |
|-------|------------|
| 3 | Numbered or bulleted list of specific criteria. Each criterion describes what PASS looks like. |
| 2 | Criteria listed but some are vague ("check for quality") or incomplete. |
| 1 | No explicit criteria. The AI is expected to decide what to check. |

## Criterion 4: Output Format (Score: __ /3)

**Is the expected output specifically described?**

| Score | Description |
|-------|------------|
| 3 | Output fully specified: table with column names, or report structure with section headings, or exact JSON shape. |
| 2 | Some structure defined but parts are left open-ended. |
| 1 | No output format. The AI decides how to present results. |

## Criterion 5: Boundaries / Constraints (Score: __ /3)

**Does the skill define what NOT to do?**

| Score | Description |
|-------|------------|
| 3 | Clear "Do NOT" statements: "Do NOT modify code", "Do NOT add sections", "Output ONLY the table." |
| 2 | Some limits implied but not explicitly stated. |
| 1 | No boundaries. The AI could modify files, generate excessive output, or go off-scope. |

**Feedback:**

## Criterion 6: Flexibility — $ARGUMENTS (Score: __ /3)

**Does the skill work on any relevant input, not just one hardcoded file?**

| Score | Description |
|-------|------------|
| 3 | Uses `$ARGUMENTS` appropriately. Works on any file the user specifies. |
| 2 | Uses `$ARGUMENTS` but in a limited or unclear way. |
| 1 | No `$ARGUMENTS`. Skill is hardcoded to a specific file or input. |

## Criterion 7: Testability (Score: __ /3)

**Can you run this skill right now and get consistently useful output?**

| Score | Description |
|-------|------------|
| 3 | Ran it. Got useful, structured output. Works as described. |
| 2 | Ran it. Output was partially useful or inconsistent with stated format. |
| 1 | Could not run it (errors, missing context) or output was not useful. |
